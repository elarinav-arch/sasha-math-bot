# Мур-математика: диалог знакомства при регистрации

**Дата:** 2026-08-17
**Статус:** утверждено

## Цель

Сейчас регистрация — одна команда `/join КОД`, после которой бот молча создаёт
профиль ребёнка, взяв имя из его Telegram-профиля (`first_name`). Это работает,
но безлико: ребёнок не видит приветствия, не может представиться сам — бот
просто решает за него, как его зовут.

Нужен более тёплый и явный первый контакт: приветствие, кнопка «Старт»,
затем код-приглашение, затем — бот сам спрашивает у ребёнка, как его зовут.
Команда `/join КОД` как отдельный путь одним сообщением исчезает — новый
диалог становится единственным способом присоединиться к команде.

## Флоу

1. Незарегистрированный `chatId` пишет боту что угодно первым сообщением
   (`/start`, `/join КОД`, любой текст — неважно) — это триггерит диалог.
2. Бот отвечает приветствием с inline-кнопкой **«🐾 Старт»**.
3. Ребёнок жмёт кнопку → бот просит код-приглашение.
4. Код неверный → диалог **тихо завершается**, без подсказок (та же логика
   анти-перебора, что была у `/join`: не подсказываем, что именно не так).
5. Код верный → бот спрашивает «как тебя зовут?».
6. Имя не проходит валидацию (пусто после очистки, длиннее лимита) → бот
   **один раз** просит написать иначе; если и вторая попытка не проходит —
   диалог тихо завершается (не хотим зацикливаться навечно).
7. Имя валидное → создаётся профиль ребёнка (`ChildProgress`) с этим именем,
   бот шлёт приветственное сообщение. Первая тренировка — на ближайшем окне,
   как и раньше (не пытаемся подключить ребёнка «на лету»).
8. Если на любом шаге (2)–(6) ребёнок не отвечает **5 минут** — диалог тихо
   завершается. Ничего не сохраняется; захочет — начнёт заново с шага 1 при
   следующем сообщении боту.
9. Уже зарегистрированный ребёнок, написавший что-либо вне тренировки —
   поведение не меняется (существующий ответ «Ты уже в команде!» для `/join`,
   либо тишина для прочего — вне рамок этой фичи).

## Тексты сообщений (черновик, можно поправить при реализации)

| Момент | Текст |
|---|---|
| Приветствие | «🐱 Привет! Я бот «Мур-математика» — помогаю тренировать таблицу умножения и собирать карточки с котиками. Готов(а) начать?» + кнопка **«🐾 Старт»** |
| После кнопки | «Отлично! Введи код-приглашения, который тебе дали:» |
| Код неверный | *(тишина)* |
| Код верный | «Ура, код верный! 🎉 А как тебя зовут?» |
| Имя не прошло (1-я попытка) | «Хм, попробуй короче и без лишнего, например «Саша» 🙂» |
| Имя не прошло (2-я попытка) | *(тишина, диалог завершён)* |
| Готово | «Приятно познакомиться, {имя}! 🐾 Ты в команде «Мур-математика». Первая тренировка — на ближайшем окне (14:00 / 17:00 / 19:00 по Кипру).» |

## Валидация имени

- Обрезать пробелы по краям, схлопнуть внутренние повторы пробелов.
- Длина после очистки: 1–30 символов. Пусто после очистки — невалидно.
- Никакой более глубокой проверки (без фильтра на язык/эмодзи/спецсимволы) —
  бот приватный, семейный, круг участников контролируется кодом-приглашением.

## Архитектура

### `dispatchUpdates` учится понимать нажатия кнопок

Telegram присылает нажатие inline-кнопки отдельным типом события —
`callback_query`, не `message`. Расширяем `Update` (`src/telegram.ts`), чтобы
он мог содержать `callback_query` наравне с `message`, и `dispatchUpdates`
нормализует и то, и другое в один и тот же `DeliveredMessage {chatId, text,
fromName}` — для `callback_query` `text` берётся из данных кнопки
(`callback_query.data`).

Ключевое следствие: **`TelegramPoller.waitFor` не меняется вообще.** Нажатие
кнопки с точки зрения уже существующего и проверенного механизма ожидания
неотличимо от обычного текстового ответа — просто пришло сообщение с нужным
`chatId`.

### `TelegramPoller` — одна новая обязанность

В `pollOnce` при получении `callback_query` в пачке обновлений поллер (помимо
обычной маршрутизации через `dispatchUpdates`) вызывает
`tg.answerCallbackQuery(id)` — без этого кнопка у ребёнка в Telegram-клиенте
будет вечно показывать «крутилку» после нажатия.

### `Telegram` — два новых метода

- `answerCallbackQuery(callbackQueryId: string): Promise<void>`
- `sendMessageWithButton(chatId, text, buttonText, callbackData): Promise<void>`
  — отправка сообщения с одной inline-кнопкой (reply_markup с inline_keyboard).

### `src/registration.ts` — от чистой функции к диалогу

Текущая `tryJoin` — чистая синхронная функция на одно сообщение — уходит.
Вместо неё:

- `validateName(raw: string): string | null` — чистая, тестируемая отдельно
  (обрезка/схлопывание пробелов, проверка длины 1–30).
- `runOnboarding(poller, tg, team, inviteCode, chatId, fromName, now): Promise<void>` —
  асинхронный оркестратор диалога: шлёт сообщение → `poller.waitFor(chatId,
  ONBOARDING_STEP_TIMEOUT_MS)` → в зависимости от ответа либо идёт дальше,
  либо тихо завершается. По структуре аналогична тому, как `runChildSlot` в
  `index.ts` уже ведёт тренировочную сессию через `PolledIO`.

### `src/index.ts` — подключение

`handleUnmatched` вызывает `runOnboarding` вместо `tryJoin`. Обёртка
`handleUnmatchedSafely` (уже существует, добавлена при финальном ревью
командного режима) остаётся без изменений — она гарантирует, что упавший
или зависший диалог одного ребёнка не блокирует и не роняет остальных.

Новая константа `ONBOARDING_STEP_TIMEOUT_MINUTES = 5`, по аналогии с
`WINDOW_MINUTES`/`BONUS_WINDOW_MINUTES`.

## Тестирование

- `validateName` — юнит-тесты: пусто, пробелы схлопываются, ровно на границе
  длины (30 ок, 31 нет), нормальное имя.
- `dispatchUpdates` — новые тесты: `callback_query` корректно превращается в
  `DeliveredMessage`, смешанная пачка из `message` и `callback_query`
  маршрутизируется правильно.
- `TelegramPoller` — тест, что `callback_query` в пачке триггерит вызов
  `answerCallbackQuery`.
- `runOnboarding` — интеграционные тесты (fake `Telegram`/`TelegramPoller`,
  по образцу уже существующих тестов на `runChildSlot`/
  `handleUnmatchedSafely`): счастливый путь целиком, неверный код (тишина),
  невалидное имя с одной переспросом и итоговым отказом, таймаут на любом
  шаге.

## Вне рамок (YAGNI)

- Кнопка «отмена»/«назад» в диалоге.
- Редактирование имени после регистрации.
- Более двух попыток ввода имени.
- Более глубокая валидация имени (фильтр языка, эмодзи, профанити).
- Сохранение состояния диалога между запусками бота (весь диалог — в памяти
  одного запуска, как и тренировочные сессии).
